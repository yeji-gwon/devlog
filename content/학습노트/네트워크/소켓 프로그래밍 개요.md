### 네트워크 프로그래밍이란

네트워크로 연결되어 있는 서로 다른 두 컴퓨터가 데이터를 주고받을 수 있도록 하는 것,
물리적 연결과 소프트웨어적인 데이터 송수신 방법이 필요하다.
소프트웨어적인 데이터 송수신 방법은 운영체제가 소켓이라는 형태로 제공하기 때문에, 데이터 송수신의 원리를 이론적으로 몰라도 소켓을 사용해서 데이터를 주고받을 수 있다.

### 소켓이란

소켓은 통신의 종단점으로, 소켓을 생성해서 관련 함수를 호출해 통신한다.
소켓은 운영체제가 제공하는 통신 인터페이스(API)로, 프로그램은 이 소켓을 통해 저수준 네트워크 프로토콜(TCP/IP 등)을 몰라도 데이터 송수신이 가능하다. 
>즉 소켓은 네트워크 통신을 위해 OS가 제공하는 추상화된 인터페이스 

### 소켓의 구성 (IP + Port)

소켓의 주소는 **IP + Port** 두 가지로 구성된다.
- **IP** : 인터넷에 연결된 컴퓨터 (호스트)를 식별
- **PORT** : 한 컴퓨터 안에서 실행 중인 여러 프로그램(소켓) 중 어느 프로그램인지 식별
-> 정확한 목적지 프로그램까지 데이터가 도달하려면 IP 주소와 포트 번호가 필요함

### 동작 방식

- **서버** : 소켓을 열고 클라이언트의 연결 요청 대기
- **클라이언트** : 서버의 IP와 포트를 통해 소켓 연결 요청
- **데이터 교환** : 연결이 되면 양쪽 소켓을 통해 실시간으로 자유롭게 데이터를 주고받음

### 주요 함수
| 함수          | 기능                              |
| ----------- | ------------------------------- |
| `socket()`  | 소켓 생성                           |
| `bind()`    | IP 주소와 Port 번호 할당               |
| `listen()`  | 연결 요청 대기 상태로 전환 (대기 큐 생성)       |
| `accept()`  | 큐에서 연결 요청을 꺼내 수락하고, 통신용 새 소켓 생성 |
| `connect()` | 클라이언트가 서버로 연결 요청                |
| `close()`   | 소켓 닫기                           |

### 소켓 타입 : 연결지향형 vs 비연결지향형

- **연결지향형 (TCP)** : 신뢰성이 있고 순서를 보장하는 데이터 경계가 없는 (스트림)
- **비연결지향형 (UDP)** : 손실 가능, 빠른 전송, 데이터 경계 있음 (데이터그램)

### 리눅스에서 소켓

- Everything is a file
- 리눅스는 소켓도 파일 디스크립터로 취급, 일반 파일/파이프/디바이스/소켓 모두 동일한 자료구조 
- 그래서 `read()`, `write()` 같은 저수준 파일 입출력 함수를 소켓에도 그대로 사용 가능

### 윈도우에서 소켓

- 소켓을 위한 별도의 API (Winsock2)를 제공
- 파일 핸들과 소켓 핸들을 커널 내부적으로 다른 방식으로 관리
- 윈도우의 파일 시스템 I/O와 네트워크 I/O(Winsock)은 역사적으로 서로 다른 서브시스템으로 설계됨
- 그래서 `ReadFile()`, `WriteFile()` 같은 일반 파일 함수를 소켓에 바로 쓸 수 없고, `recv()`, `send()` 같은 전용 함수를 써야 함
