#### 0. 목적

패킷에 저장된 주소 (MAC/IP/포트)들이 무엇을 식별하고, 라우팅 과정에서 어떻게 쓰이는지 이해


#### 1. 세 가지 주소 개요

네트워크에서 기기와 프로그램을 찾기 위해 사용하는 고유한 식별 번호들

| 구분     | 식별 대상            | 성격     | 계층        |
| ------ | ---------------- | ------ | --------- |
| MAC 주소 | NIC (랜카드)        | 물리적 주소 | L2 (링크)   |
| IP 주소  | 네트워크상의 호스트 (종단점) | 논리적 주소 | L3 (네트워크) |
| 포트 번호  | 호스트 내 프로세스       | 논리적    | L4 (전송)   |


#### 2. NIC와 IP 주소의 관계

>NIC = 문, IP = 문패

- NIC는 **물리적 실체** - 보통 1개
- IP는 그 NIC에 **소프트웨어적으로 붙이는 이름표** - 기본 1개, 필요시 n개까지 바인딩 가능
- MAC은 NIC 자체를 가리키므로 1:1
- IP는 NIC가 네트워크 계층에서 호스트로서 불리는 이름으로, 하나의 NIC에 여러 IP를 바인딩하면 다른 장치들 입장에서 마치 호스트가 여러 개 있는 것처럼 인식됨


#### 3. 라우팅 과정에서 주소들이 쓰이는 방식

1. 캡슐화 구조
```
[이더넷 헤더] [IP 헤더][TCP/UDP 헤더][데이터]
  MAC 정보    IP 정보    포트 정보 
```

2. 전체 여정에서 주소 변화

| 주소        | 여정 중 변화                  |
| --------- | ------------------------ |
| 목적 IP     | 출발지 ~ 최종 목적지까지 **고정**    |
| 출발/목적 MAC | **매 홉(hop)마다 교체됨**       |
| 포트 번호     | 최종 목적지에서만 사용, 라우팅 중엔 안 봄 |

 3. 라우터가 매 홉마다 반복하는 작업
	 1. 프레임 수신 → 이더넷 헤더 탈캡슐화
	 2. **IP 헤더의 목적 IP 확인** (단, 호스트 부분은 안 보고 **네트워크 주소 부분만** 라우팅 테이블과 대조)
	 3. 라우팅 테이블 조회 → 가장 구체적인 대역 선택
	 4. 다음 홉의 MAC 주소 확보
	 5. 새 이더넷 헤더로 재캡슐화 (출발 MAC = 이 라우터, 목적 MAC = 다음 홉)
	 6. 다음 라우터로 전송
	 7. 목적지에 도착할 때까지 반복
	    
4. 최종 목적지 도착 후
	1. 이더넷 헤더 확인 → 내 MAC 맞음 → 벗김
	2. IP 헤더 확인 → 내 IP 맞음 → 벗김
	3. TCP/UDP 헤더 확인 → 포트 번호 확인 → 해당 포트를 리스닝 중인 프로세스의 소켓으로 데이터 전달



#### 4. 비유 정리

- **IP = 최종 배송지 주소** (택배 송장, 끝까지 안 바뀜)
- **MAC = 구간마다 인계하는 다음 트럭 기사** (홉마다 바뀜)
- **포트 = 그 집 안의 몇 호수/누구 앞** (최종 수신자)
