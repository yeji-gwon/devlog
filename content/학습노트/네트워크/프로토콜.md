
#### 프로토콜이란?

프로토콜(Protocol)은 서로 다른 주체들이 통신하거나 상호작용할 때 지켜야 하는 **약속이나 규칙**이다.
"무엇을, 어떤 형식으로, 어떤 순서로, 어떤 의미로 주고받을 것인가"를 정한다.

예를 들어 채팅 서버에서 다음과 같은 규칙을 정할 수 있다.
```
C → S : LOGIN|Alice
C → S : CHAT|Hello
C → S : QUIT
```
서버가 `LOGIN|Alice`를 받으면 로그인 요청으로 해석하고, `CHAT|Hello`를 받으면 채팅 메시지로 해석한다고 정하는 것이다.

이처럼 **프로토콜은 데이터의 형식뿐만 아니라 데이터의 의미와 처리 방법까지 정의한다.**


#### 추상화 관점에서 보기

네트워크에서 데이터를 전달하려면 데이터 유실, 순서 변경, 재전송, 네트워크 혼잡 등 여러 문제를 고려해야 한다.
하지만 애플리케이션이 이러한 네트워크의 세부적인 동작을 직접 처리하는 것은 부담스럽다.

그래서 전송 계층의 프로토콜은 이러한 복잡한 동작을 숨기고, 애플리케이션이 사용할 수 있는 **통신 모델로 추상화**해서 제공한다.
TCP와 UDP는 이 통신 모델을 서로 다르게 제공한다.
- TCP → **신뢰성 있는 바이트 스트림**
- UDP → **데이터그램**

따라서 TCP와 UDP의 차이를 이해할 때는 단순히 기능의 차이로 보기보다, **애플리케이션에 어떤 추상화를 제공하는가**를 중심으로 보는 것이 좋다.


#### TCP, 신뢰성 있는 바이트 스트림

TCP는 애플리케이셔넹 **신뢰성 있는 바이트 스트림**이라는 추상화를 제공한다.

> 연결된 상대와 신뢰성 있는 하나의 바이트 흐름을 주고받는다.

TCP는 내부적으로 순서 번호, ACK, 재전송, 흐름 제어, 혼잡 제어 등을 사용해 데이터의 신뢰성 있는 전달을 처리한다.

따라서 애플리케이션은 이러한 네트워크의 세부적인 문제를 직접 처리하지 않고, **연속적인 바이트 스트림**을 사용할 수 있다.


#### 바이트 스트림

TCP에서는 애플리케이션이 보낸 `send()`단위가 그대로 전달된다는 보장이 없다.

```
send("HELLO");
send("WORLD");
```
라고 했더라도 수신 측에서는
```
HELLOWORLD
```
로 한 번에 받을 수도 있고,
```
HEL
LOWOR
LD
```
처럼 여러 번에 나누어 받을 수도 있다.

TCP에게 중요한 것은 `HELLOWORLD`라는 **바이트의 연속**이지, `HELLO`와 `WORLD`라는 애플리케이션의 메시지 경계가 아니다.
따라서 **TCP에는 메시지 경계가 없다.**

애플리케이션에서 메시지 단위가 필요하다면 별도의 프로토콜을 정의해야 한다.
예를 들어 메시지 앞에 길이를 붙일 수 있다.
```
[5][HELLO][5][WORLD]
```
또는 구분자를 사용할 수도 있다.
```
HELLO\n
WORLD\n
```

즉, TCP가 제공하는 것은 **바이트 스트림**이고, 그 바이트를 어떻게 메시지로 구분할지는 애플리케이션의 책임이다.


## UDP → 데이터그램

UDP는 애플리케이션에 **데이터그램(datagram)​**이라는 추상화를 제공한다.

> **각각의 데이터를 독립적인 하나의 전송 단위로 주고받는다.**

예를 들어
```
sendto("HELLO");
sendto("WORLD");
```
라고 하면 `HELLO`와 `WORLD`는 각각 별개의 데이터그램이다.

따라서 UDP에서는 **데이터그램의 경계가 유지된다.**
```
첫 번째 데이터그램 → HELLO
두 번째 데이터그램 → WORLD
```
다만 UDP는 TCP와 달리 데이터의 전달을 보장하지 않는다.

따라서
- 데이터가 유실될 수 있고
- 순서가 뒤바뀔 수 있으며
- 재전송도 해주지 않는다.

예를 들어
```
송신: HELLO → WORLD → !!!!!
수신: HELLO → !!!!! 
```
처럼 `WORLD`가 유실될 수 있다.

또는
```
송신: HELLO → WORLD
수신: WORLD → HELLO
```
처럼 순서가 바뀔 수도 있다.

필요하다면 이러한 기능을 **애플리케이션에서 직접 구현해야 한다.**


## 추상화가 설계에 미치는 영향

TCP와 UDP의 차이는 단순히 **TCP는 신뢰성이 있고 UDP는 빠르다.** 라고 이해하는 것보다,

**TCP와 UDP가 애플리케이션에 서로 다른 통신 추상화를 제공한다.** 라고 이해하는 것이 중요하다.

TCP를 선택하면 애플리케이션은 **바이트 스트림**을 다루게 된다.
따라서 채팅 메시지처럼 별도의 메시지 단위가 필요하다면 **메시지 경계를 애플리케이션 프로토콜에서 직접 정의해야 한다.**

반대로 UDP를 선택하면 애플리케이션은 **데이터그램**을 단위로 사용할 수 있다.
대신 데이터그램의 유실이나 순서 뒤바뀜 등을 허용할 것인지, 필요하다면 어떻게 처리할 것인지를 애플리케이션에서 결정해야 한다.

결국 **어떤 추상화를 제공하느냐가 그 위에서 동작하는 프로그램의 설계 방식에도 영향을 준다.**
