#### 1. 람다란?

이름 없는 함수 객체를 그 자리에서 즉석으로 정의하는 문법
C++11 도입
컴파일러가 내부적으로 **함수 객체(functor) 클래스**를 자동 생성

```cpp
// 람다 없이 - functor 클래스 직접 정의
struct IsEven {
	bool operator()(int x) const { return x % 2 == 0; }
};

// 람다로 - 그 자리에서 바로
[](int x) { return x % 2 == 0; }
```

STL 알고리즘 조건자, 정렬 기준, 콜백처럼 **그 자리에서만 쓰고 버릴 함수**를 만들 때 유용

#### 2. 전체 문법

```cpp
[캡쳐](매개변수) mutable exception -> 반환타입 {본문}
```

| 파트        | 설명                             |
| --------- | ------------------------------ |
| `[캡쳐]`    | 외부 변수를 어떻게 가져올지                |
| `(매개변수)`  | 일반 함수처럼 인자 목록                  |
| `mutable` | 값 캡쳐한 변수를 내부에서 수정 가능하게 (생략 가능) |
| `-> 반환타입` | 대부분 생략, 컴파일러가 추론               |
| `{본문}`    | 실행 코드                          |


#### 3. 내부 동작

```cpp
// [x](int a) { return a + x; }는 대략 이렇게 컴파일됨
class __Lambda {
	int x; // 캡쳐한 변수는 멤버 변수가 됨
public:
	__Lambda(int x) : x(x) {}
	auto operator()(int a) const { return a + x; }
};
```
캡쳐한 변수는 이 클래스의 **멤버**로 저장됨 (값 캡쳐 = 멤버에 복사본 저장, 참조 캡쳐 = 참조자를 멤버로 저장)

**타입**
각 람다는 컴파일러가 만든 **고유한 익명 타입**을 가짐 → `auto`로만 받을 수 있음

```cpp
auto a = [](int x) { return x + 1; }
auto b = [](int x) { return x + 1; }
// a와 b는 본문이 완전히 똑같아도 서로 다른 타입
// 각각 컴파일러가 __Lamda_1, __Lamda_2 같은 별개의 클래스로 만듦
// 고유하다 = 람다 표현식이 작성될 때마다 그 자리에 새로운 클래스가 만들어짐
// 익명 = 이름이 없으니 그 타입을 코드에서 직접 쓸 수 없어
```

멤버 변수/컨테이너 등 고정 타입이 필요한 곳에는 담을 수 없어서, 개별 타입 차이를 감춰줄 "공통 타입"이 필요함
`std::function<반환타입(매개변수들)>` 은 시그니처만 같으면 내부적으로 뭐가 있든 (람다든, 함수 포인터든 펑터든) 다 담을 수 있는 통일된 타입으로 감싸서 타입 지우기
```cpp
std::vector<std::function<int(int)>> ops;
ops.push_back([](int x) { return x + 1; });
ops.push_back([](int x) { return x + 2; });
// 둘 다 std::function<int(int)>라는 같은 걸 타입으로 감싸져서 같은 vector에 들어갈 수 있음
```


#### 4. 캡쳐

캡쳐는 람다가 정의된 스코프의 외부 변수를 내부에 어떻게 가져다 쓸지 정하는 것

1. 값 캡쳐 `[x]`
	- 캡쳐 시점의 값을 **복사**해서 클로저 객체 멤버로 저장
	- 원본이 나중에 바뀌어도 영향 없음
	- 기본적으로 `operator()`가 `const`라서 람다 내부에서 **수정 불가**
```cpp
int x = 10;
auto lambda = [x](){ return x + 1; }
x = 20;
lambda(); // 11 (캡쳐 시점 값 복사, 이후 변경 반영 안됨)
```

2. 참조 캡쳐 `[&x]`
	- 원본 변수를 **참조**로 저장 → 원본 직접 수정 가능
	- `operator()`가 `const`여도 참조가 가리키는 대상은 수정 가능 (const가 막는 건 람다 객체 자신의 멤버를 바꾸는 것이지 참조 대상이 아님)
>[!warning] 댕글링 참조
>람다가 함수 스코프보다 오래 살아남는 경우(비동기 콜백, 이벤트 핸들러 등록) 특히 위험. 이때는 값 캡쳐로 바꿔야 안전
>```cpp
>std::function<void()> MakeLambda() {
>	int local = 10;
>	 return [&local]() { std::cout << local; } // 함수 끝나면 local 소멸
>	 // 나중에 호출 시 UB
>}
>```


3. 전체 캡쳐

| 문법        | 의미                    |
| --------- | --------------------- |
| `[=]`     | 사용하는 모든 외부 변수를 값으로 캡쳐 |
| `[&]`     | 사용하는 모든 외부 변수를 참조로 캡쳐 |
| `[&, x]`  | 기본 참조, x만 값으로         |
| `[=, &x]` | 기본 값, x만 참조로          |

4. this 캡쳐
```cpp
class Foo {
	int value;
	void bar() {
		auto lambda = [this]() { return value; }; // this->value
		// C++17 [*this]로 객체 자체를 값 복사해서 캡쳐 가능
	}
};
```
>[!warning] this 댕글링 객체가 소멸된 후 `[this]`로 캡쳐한 람다를 호출하면 UB
>스마트 포인터 사용 시 `[weak_this = weak_from_this()]`처럼 `weak_ptr`로 캡쳐하는 패턴 사용


5. 초기화 캡쳐
```cpp
auto ptr = std::make_unique<int>(5);
auto lambda = [p = std::move(ptr)]() { return *p; };
```
